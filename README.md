# 0.25 m/s

The speed of light, slowed down until a Roomba wins. This is a 29-second Blender film for the RenderJuice "Speed" contest. The whole film is generated by Python scripts: geometry, materials, animation, camera, titles and soundtrack. Nothing is modelled, keyframed or recorded by hand, and no assets are imported.

## The idea in numbers

| | |
|---|---|
| Speed of light in the film | 0.25 m/s (299,792,458 m/s ÷ 1,199,169,832) |
| Roomba | 0.30 m/s, leaves 1.5 s after the switch |
| Bulb to cat | 6.01 m, so the light needs 24.05 s |
| Roomba's route | 4.93 m, it bumps the bed 16.4 s after setting off |
| Margin | the Roomba wins by 6.1 s |

## How the light works

An empty called `Front` sits at the bulb. Its uniform scale *is* the radius of the light front, keyed linearly so that r = 0.25 m/s × t. A second empty, `FrontOrigin`, sits at the same point with unit scale. Every material in the scene runs through one shader node group, `WaveFront`, which reads both empties through Texture Coordinate › Object:

- d = |position in FrontOrigin space| is the distance from the bulb in metres
- q = |position in Front space| = d / r
- r − d = d/q − d is positive inside the light and negative outside, and a thin band around zero glows as the front

No drivers and no per-object keyframes are involved. Drivers on node values made EEVEE re-sync every material on every frame.

## Files

| File | What it does |
|---|---|
| `build_scene.py` | Builds the entire `.blend` from an empty scene |
| `hud.py` | Frame-change handler that writes the on-screen readout (time, front distance) |
| `final_setup.py` | Loaded by every render process: registers the HUD and sets resolution and samples |
| `render_final.py` | Resumable renderer: one Blender process per frame, with a stall watchdog |
| `audio.py` | Synthesises the soundtrack sample by sample (pure Python, no samples) |
| `assemble.py` | Frames + soundtrack → H.264/AAC MP4, loudness-normalised to −16 LUFS |
| `wip_shot.py` | Takes the work-in-progress screenshot inside Blender's own UI |
| `race_chart.py` | Draws the distance–time chart of the race from the same constants |

## Reproduce the film

You need Blender 4.5 LTS, Python 3 and ffmpeg.

```bash
blender --background --python build_scene.py -- speed.blend 960 540 16
mkdir -p audio && python3 audio.py audio/soundtrack.wav
BLENDER=$(which blender) python3 render_final.py out/final 200 16 1
python3 assemble.py out/final final.mp4
```

`200` means 200 % of 960×540, which is 1920×1080. The last `1` renders one frame per Blender process: on the integrated GPU this was made on, only the first EEVEE render in a session was fast. As a check, the scene was rebuilt from these scripts and four frames (120, 280, 520, 650) were re-rendered. Three matched the published frames bit for bit; the fourth differed imperceptibly (PSNR 63.6 dB). `audio.py` reproduces the soundtrack byte for byte.
